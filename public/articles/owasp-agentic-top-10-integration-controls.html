The OWASP Agentic Top 10, mapped to integration controls

Security teams now have a shared list of agent risks. Integration teams own many of the controls. This guide connects the two, risk by risk.

OWASP Agentic Top 10 (2026 edition) By Rameshkumar Varanganti · Enterprise Integration Lead & Architect · Updated 31 October 2026 · 13 min read

In December 2025 the OWASP GenAI Security Project published the Top 10 for Agentic Applications, a peer-reviewed list built by more than a hundred practitioners. It extends, rather than replaces, the OWASP Top 10 for LLM Applications, whose 2026 edition followed in August 2026. The LLM list is about what a model says; the agentic list is about what an agent does.

That second category is an integration problem. When an agent misbehaves, the damage happens through tool calls, API requests and messages to other agents, which is to say through the gateways, API policies and integration flows that integration teams design and run. This guide maps each risk to the controls that live in those layers.

The ten risks and where to control them

IDRiskWhat it looks like in an integration landscapePrimary integration controls
ASI01Agent goal hijackA supplier note in an invoice PDF tells the AP agent to change the bank account before paymentTreat tool results and documents as data; approval gates on payments and master-data changes; allow-listed write tools only
ASI02Tool misuse and exploitationAn agent with a generic "call ERP API" tool deletes or mass-updates records it was only meant to readNarrow, task-shaped tools; strict input schemas; read and write split across servers; per-tool authorization in the MCP gateway
ASI03Identity and privilege abuseAn HR copilot uses a technical user with full Employee Central access to answer any employee's questionUser context on every call; agent registered as its own client; downstream token exchange with minimal scope; no shared technical users
ASI04Agentic supply chain vulnerabilitiesA community MCP server or unsigned Agent Card is installed and quietly exfiltrates dataApproved registry of MCP servers and Agent Cards; verified signatures; pinned versions; egress allow-lists
ASI05Unexpected code executionAn agent generates a Groovy script or SQL and a tool runs it against a live tenantNo tools that execute model-written code in production; sandboxed execution only; human review before deployment
ASI06Memory and context poisoningA poisoned knowledge-base article makes the support agent recommend disabling a validation stepProvenance on retrieved content; write controls on agent memory and RAG stores; periodic review of high-impact memories
ASI07Insecure inter-agent communicationA spoofed partner agent sends A2A messages that your procurement agent trustsSigned Agent Cards; mutual authentication; A2A traffic through an agent gateway; message size and rate limits
ASI08Cascading failuresOne agent's retry loop floods an iFlow, which backs up the ERP queue and stalls order processingRate limits and quotas per agent; circuit breakers; timeouts shorter than the agent's; idempotent writes; bulkheads between agent and human traffic
ASI09Human-agent trust exploitationAn agent presents a confident but fabricated summary, and an approver clicks "approve" without checkingApproval screens show the actual payload and source data, not the agent's summary; four-eyes on high-value actions; approval rate monitoring
ASI10Rogue agentsA misconfigured or compromised agent keeps acting outside its mandatePer-agent kill switch at the gateway; behavioural baselines and anomaly alerts; short-lived credentials; regular access recertification

Which layer owns which control

Defence in depth matters more for agents than for ordinary API consumers, because an agent picks its own calls at runtime. Spread the controls so no single misconfiguration exposes a system of record:

  • Agent platform: system prompts, tool selection, memory hygiene, user-facing approvals.
  • MCP / agent gateway: client authentication, per-tool authorization, filtered discovery, quotas, payload inspection, audit, kill switch. Covers most of ASI02, ASI03, ASI07, ASI08 and ASI10.
  • API management: OAuth scopes, token exchange, threat protection, spike arrest, consumer analytics.
  • Integration flows: input validation, business rules, idempotency, compensation, data masking in logs. The last line before the system of record.
  • Systems of record: their own authorization checks. Never assume the gateway did it.

Approval gates that actually work

Approval gates are the most common mitigation and the most commonly weakened one (ASI09). Design rules from production:

  1. Gate on impact, not on tool. Reading a balance needs no approval; changing a bank account always does, regardless of which tool does it.
  2. Show the payload. The approver sees the vendor ID, old and new IBAN and the source document, not a sentence the agent wrote.
  3. Make the approval a separate, authenticated event. MCP's Multi Round-Trip Requests and A2A's INPUT_REQUIRED state both make this natural: the approval arrives as its own request, from a human identity, and is logged.
  4. Watch approval rates. A 99% approval rate means the gate is theatre. Sample and review.

The regulatory clock for agent governance

Two timelines shape how much evidence you will need to show, especially for HR and finance agents.

DateMilestoneRelevance to agentic integration
2 Feb 2025EU AI Act prohibited practices and AI literacy duties applyAlready in force
2 Aug 2025EU AI Act obligations for general-purpose AI models applyMostly on model providers; deployers inherit documentation
Feb 2026NIST launches the AI Agent Standards Initiative; NCCoE concept paper on agent identity and authorizationSignals that agent identity, audit and non-repudiation will become baseline expectations in the US
Jun 2026EU Digital Omnibus on AI adopted by Parliament (16 June) and Council (29 June)Defers high-risk obligations; does not remove them
2 Dec 2027High-risk obligations for Annex III systems apply (deferred from Aug 2026)Annex III includes employment and HR uses: recruitment, promotion, task allocation, performance monitoring
2 Aug 2028High-risk obligations for AI in Annex I regulated products applyRelevant to manufacturing and medical device landscapes

The deferral is breathing room, not a reprieve. Logging, human oversight and traceability for high-risk uses take longer to build than most teams expect, and integration layers produce most of the evidence: who called what, with which data, under whose authority. If you design the audit trail now, compliance later is mostly reporting.

A starting checklist

  • Inventory every agent, the tools and agents it can reach, and the data classes involved.
  • Map each agent to ASI01 to ASI10 and record the control and owning team for each risk.
  • Route all MCP and A2A traffic through a gateway with per-tool authorization and a kill switch.
  • Remove shared technical users from agent paths; carry user identity end to end.
  • Require approval for payments, bank data, master data, HR decisions and anything irreversible.
  • Make every agent-reachable write idempotent and compensatable.
  • Log metadata with correlation IDs; mask personal data; retain to your regulatory horizon.
  • Flag agents that touch Annex III areas (HR, credit, access to essential services) for EU AI Act readiness.
  • Red-team with indirect prompt injection in documents, tool results and partner-agent messages.

Frequently asked questions

How is the OWASP Agentic Top 10 different from the OWASP LLM Top 10?

The LLM Top 10 covers risks in model behaviour and output, such as prompt injection and data leakage. The Agentic Top 10 covers risks in autonomous action: goal hijacking, tool misuse, identity abuse, inter-agent communication, cascading failures and rogue agents. Agent systems should be assessed against both.

Which agentic risks can an MCP gateway mitigate?

A gateway is the natural control point for tool misuse (ASI02), identity and privilege abuse (ASI03), insecure inter-agent communication (ASI07), cascading failures (ASI08) and rogue agents (ASI10), through per-tool authorization, quotas, audit and kill switches. It cannot fix goal hijacking or memory poisoning on its own.

When do EU AI Act high-risk rules apply to HR agents?

After the Digital Omnibus adopted in June 2026, high-risk obligations for Annex III systems, which include many employment and HR uses, apply from 2 December 2027. Prohibited practices and general-purpose AI obligations already apply.
