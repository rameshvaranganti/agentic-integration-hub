Definition

What is agentic integration?

Agentic integration, also called agent integration or AI agent integration, connects AI agents to enterprise applications, data, events and other agents so they can take real actions safely. Agents choose their next step at runtime, so they reach systems through MCP tools, delegate through A2A, and pass gateways that apply identity, policy, approvals and audit, while your existing APIs and integration flows still do the work.   • IdentityTechnical users → User + agent + service on every call

How agentic integration works, end to end

Every agent action follows one governed path

Whether one agent answers a question or several settle an invoice dispute, each step has a control that integration and security teams can own.

  • Narrow MCP tools over your managed APIs
  • A2A for delegating to other agents
  • Gateways in front of every agent-facing endpoint

Several agents, one governed process

An orchestrator delegates to specialist agents, each with narrow tools. Example: an invoice fails the three-way match; procurement checks the PO, the supplier's agent confirms delivery over A2A, finance requests payment, and policy routes 48,000 to an AP manager.

  • Supervisor, hand-off, fan-out and workflow-led patterns
  • Permissions narrow at every delegation hop
  • Depth limits, budgets and loop protection

Policy in action: allow, deny or ask a human

Rules are explicit, versioned and enforced outside the agent, so a confused or manipulated agent still cannot exceed them.

# illustrative policy-as-code
policy: supplier-payments
applies_to: { agents: [finance-agent] }
rules:
  - deny:    supplier.status == "blocked"
  - deny:    bank_details_changed_days < 30
  - approve: amount > 10000   # 4-eyes
  - allow:   amount <= 10000 and po_match
limits: { calls_per_min: 20, max_depth: 2 }
Governance and security policies guide →
  • Finance agent pays 4,200 on a matched POAllow
  • Same agent and user pay 48,000Approve first
  • Procurement agent calls create_payment_requestDeny
  • Supplier email: "pay to our new bank account"Deny + alert
  • Engines such as Open Policy Agent or Cedar express rules like these; gateway, API management and the system of record each enforce their part.

Defense in depth for AI agents

No single control makes an agent safe. Six layers work together, each mapped to the OWASP Top 10 for Agentic Applications, from goal hijack (ASI01) to rogue agents (ASI10).
